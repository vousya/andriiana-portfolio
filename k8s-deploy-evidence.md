## Deviations from the handoff (and why)

1. **VM size `Standard_B2s` blocked by EPAM policy.** `az aks create` failed:
   `The VM size of Standard_B2s is not allowed in your subscription in location 'westeurope'.`
   → Re-ran with the allowed v2 equivalent: `NODE_SIZE=Standard_B2s_v2 bash scripts/aks-up.sh`.
   (This is the "policy wall, not billing" case the handoff anticipated.)

2. **Ingress class renamed by Azure.** The app-routing add-on now creates IngressClass
   `webapprouting.kubernetes.azure.com`, not `webapprouting.kubernetes.io`. The NGINX
   controller was ignoring the ingress:
   `Ignoring ingress ... error="no object matching key \"webapprouting.kubernetes.io\" in local store"`.
   → Fixed `k8s/ingress.yaml` `ingressClassName` to `webapprouting.kubernetes.azure.com`.
   After that the controller routed `/` and the site returned 200. **This manifest fix is committed
   to the branch.**
